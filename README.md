# 朝の狙い目レース

JRA の開催日の朝に、その日の全レースを **荒れ度** と **狙い目** で並べ、出走馬とオッズも見られるスマホ向けページです。
GitHub Actions が毎朝自動でデータを集め、GitHub Pages に置きます。
データはパスワードで暗号化しているので、パスワードを知っている人（自分）しか中身を見られません。

## しくみ

```
GitHub Actions（毎日 12:07 JST に翌日の分を先に取り込み、毎朝 7:30 JST に当日の分を取り直す。日中はページの「このレースを最新にする」ボタンで1レースずつ取り直す）
  └ python -m keiba run
      1. JRA公式サイトの出馬表で、今日が開催日か確認（違えばここで終了）
      2. 開催ページの一覧表から全レースの条件（頭数・芝ダ・距離・クラス・牝馬限定）を取得
      3. 各レースの出馬表から出走馬・単勝オッズ・ハンデ戦かどうかを取得、馬場状態も取得
      4. スコアを計算し、パスワードで暗号化して data/ に保存
  └ data/ をコミット → site/ と合わせて GitHub Pages に公開
```

| ファイル | 役割 |
|---|---|
| `keiba/fetch.py` | JRA公式サイトへのアクセス（robots.txt 遵守、2秒間隔、1回150件まで） |
| `keiba/parse.py` | HTML から項目を取り出す |
| `keiba/jra.py` | ページをたどって当日の全レースを集める |
| `keiba/score.py` | 荒れ度と狙い目の計算 |
| `keiba/crypto.py` | データの暗号化（ブラウザで復号できる形式） |
| `config.toml` | スコアの重みと得意条件 |
| `site/` | 公開ページ（HTML / CSS / JS） |
| `data/` | 毎朝の計算結果（自動でコミットされる） |

## 予想とシミュレーション

- 各馬の左の印をタップすると ◎○▲△☆✕ の順に変わります。印とメモはその端末にだけ保存されます
- 馬名をタップすると、前走〜4走前の成績（日付・競馬場・レース名・芝ダ距離・馬場・頭数・着順と着差・通過順・上がり・タイム・騎手・斤量）が開きます
- 馬名をタップした欄で、調教評価（A〜D）と調教の脚色（馬なり・G前仕掛け・強め・一杯）を入れられます。以前のシミュレーターと同じ点数（A +2・B +1・C 0・D −2、馬なり +0.5・G前 +0.25・強め 0・一杯 −0.5）でシミュレーションに反映します。JRA公式サイトには調教のデータがないので、自分で見た評価を入れます
- 馬名をタップした欄には、血統（父・母・母の父）・調教師と所属・生産者・馬主も出ます。「自分の補正（−2〜+2）」を入れると、シミュレーションに反映されます（以前のシミュレーターの「補正」と同じ重み）
- 血統の集計（`keiba/pedigree.py`）：毎回の出馬表に載っている全馬の前走〜4走前を、父・母の父ごとに貯めて（同じ走は1回だけ）、芝・ダート別の成績と2歳時の成績、芝向き・ダート向きを出します。記録は暗号化して `data/pedigree.json` に保存します
- 新馬など前走がない馬は、血統（父の2歳時と全体の成績・母の父の成績、その日の芝/ダートでの成績と向き不向き）から能力・脚質・末脚を推定してシミュレーションします。前走がある馬でも、初芝・初ダートのときは血統の向き不向きで加減点します
- 血統でも推定できない馬が多いレースでは、シミュレーション結果に注意が出ます（能力・脚質・末脚が平均扱いになり、騎手・枠・自分の補正の差だけで決まるため）
- 各レースで馬場（JRA発表／良・稍重・重・不良）と、芝はクッション値・ダートは含水率を入力できます。シミュレーションの馬場補正に使い、その端末に保存されます
- クッション値と含水率は、JRAの馬場情報ページが読み込むデータファイル（`_data_cushion.html`・`_data_moist.html`）から最新の測定値を自動で取り込みます。クッション値は入力がなければその値で計算します。含水率は競馬場ごとに基準が違うため表示のみで、自分で入力したときだけ計算に使います
- シミュレーション結果の下に「即PATを開く」と「印をコピー」のボタンがあります。即PATに買い目を自動で入れる仕組みはJRAにないので、コピーした印を見ながら即PATで入力します
- 各レースの「このレースを最新にする」ボタンは、GitHub の取得処理（`refresh.yml`）を呼び出して、そのレースのオッズ・馬体重・馬場を約1分で取り直します。使うには、ページ下の「更新ボタンの設定」に GitHub のアクセストークン（Fine-grained、このリポジトリだけ、Actions の読み書き権限だけ）を保存します。トークンはその端末にだけ保存されます
- 馬体重は発表後に取り込み、各馬の欄に表示します。シミュレーションでは、以前のシミュレーターと同じく10kg以上減（16kg以上減はさらに）と、休み明け以外の14kg以上増を減点します
- 「シミュレーション」ボタンは、以前作った「レースシミュレーター」と同じ計算（`site/sim.js`）で、前走成績から能力・脚質・末脚を出し、コースと馬場の補正をかけて5000回走らせます。オッズと人気は使いません。結果の予想印は「自分の印にする」で印に写せます
- 開催中の馬場の傾向（`keiba/bias.py`）：同じ開催の前日と当日の終わったレースの結果から、競馬場・芝ダート別に「3着以内の馬が4角で前にいたか」「内枠か外枠か」を全レースの平均と比べ、「前残り・内枠有利（6R）」のように各レースに出します。レース数が少ないうちは弱めて、シミュレーションの「前の馬の有利さ」と「枠の有利さ」に足します。結果の控えは暗号化して `data/results_raw/` に置きます（ページには載せません）
- ページ上の「この後のレースをまとめて最新にする」で、各会場の次の1〜3レースを1回の処理でまとめて取り直します（`--race 東京-10,京都-10,新潟-10`）。終わったレースの結果も取り込んで、馬場の傾向を更新します
- 毎日 17:37 に、その日のレース結果を JRA公式サイトから取り込み、シミュレーションの予想印・1番人気・自分の印と比べた結果をページの「予想と結果」に出します（`.github/workflows/evaluate.yml`）。各レースにも着順とシミュレーションの印の着順が出ます。結果のデータも暗号化して `data/results/` に置きます
- 2026年10月24日の35レースで予想印と実際の着順を比べた結果（`python -m keiba evaluate`、Actions の「予想と結果の比較」）をもとに、前走を重く・末脚を軽く・上位騎手を重く・新馬の血統推定の差を小さくしました

## スコア

- **荒れ度**: 「条件からの荒れ度」と「オッズからの荒れ度」の平均（0〜100）
  - 条件: 頭数、ハンデ戦、牝馬限定、クラス、馬場状態、芝ダと距離
  - オッズ: 1番人気の支持率、上位3頭の支持率合計、オッズのばらつき
- **狙い目**: 条件とオッズの **ズレ** と **得意条件ボーナス** の合計（0〜100）
  - ズレは同じ日のレース同士で標準化して比べます
  - 条件は荒れ寄りなのに人気が集中 → **穴狙い向き**
  - 条件は堅めなのにオッズが割れている → **本命妙味**
  - 新馬戦・障害戦・7頭以下はズレの点を割り引きます

スコアの計算では、オッズはレースを選ぶためだけに使います。印を考えるときにオッズを見たくなければ、ページの「オッズ表示」ボタンで隠せます。

重みはすべて仮の値です。`config.toml` で変えられます。

### 得意条件の設定

`config.toml` の末尾にある例を参考に `[[favorites]]` を追加してください。

```toml
[[favorites]]
name = "芝の中距離"
surface = "芝"
distance_min = 1800
distance_max = 2200
bonus = 15
```

## 初回のセットアップ

1. このブランチをデフォルトブランチ（main）にマージする。スケジュール実行はデフォルトブランチでしか動きません
2. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にする
3. **Settings → Secrets and variables → Actions → Secrets** に `PAGE_PASSWORD` を作り、ページを開くときのパスワードを設定する（未設定だと更新が失敗します）
4. （任意）**Settings → Secrets and variables → Actions → Variables** に `KEIBA_CONTACT` を作り、User-Agent に入れる連絡先（URL など）を設定する。未設定ならリポジトリの URL を使います
5. **Actions → 朝の更新 → Run workflow** を一度手動で実行し、ページが公開されることを確認する

## 手元での確認

```sh
pip install -r requirements.txt -r requirements-dev.txt
python -m pytest -q

# 架空のサンプルデータでページを見る（パスワードは sample）
python -m keiba sample
python -m keiba build-site --out .preview/site --data .preview/data
python -m http.server -d .preview/site 8000
```

## データの扱い

- データ元は JRA公式サイト（日本中央競馬会）です。netkeiba など、規約で自動取得が認められていないサイトは使いません
- 出走馬・オッズを含むデータは、パスワードで暗号化してから `data/` に保存し、ページに置きます。パスワードなしでは中身を読めないので、自分だけが私的に見る使い方になります
- パスワードを他の人に教えたり、ページの中身を転載したりしないでください（JRA のデータを私的利用の範囲を超えて公表することは規約で禁止されています）
- 調査用のワークフロー（`probe.yml`）のログは公開されるので、日本語の文字を伏せ字にして構造だけを出しています
- アクセスは robots.txt に従い、2秒以上の間隔をあけ、1回の実行で150リクエストまでに制限しています
- JRA のページ構成が変わって読み取れなくなったときは、間違ったデータを公開せずに「取得失敗」と表示し、Actions の実行を失敗扱いにします
